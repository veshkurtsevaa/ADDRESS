# ADDRESS

Статический двуязычный сайт (RU/EN) о кураторских путешествиях.
Чистые HTML/CSS/JS, без сборщика и зависимостей. GSAP + ScrollTrigger с CDN.

## Где что лежит

Четыре страницы в корне: `index.html`, `about.html`, `service.html`,
`contacts.html`. Все подключают один и тот же набор:
`styles.css` → `i18n.js` → `script.js` → GSAP с CDN → `animations.js`.

| Задача | Файлы, которых достаточно |
| --- | --- |
| Правка текста (любая страница) | `i18n.js` + соответствующий HTML |
| Hero главной | `index.html` (секция `.hero`), `styles.css` блок `hero`, `assets/video/home-hero.mp4` |
| Галерея услуг главной | `index.html` `#index`, `styles.css` баннер `HOME`, блок `home gallery` в `script.js` |
| Страница About | `about.html`, `styles.css` баннер `ABOUT` |
| Страница Service | `service.html`, `styles.css` баннер `SERVICE` |
| Форма и контакты | `contacts.html`, два баннера `CONTACTS` в `styles.css`, блоки `interest tag picker` / `contact forms` в `script.js` |
| Шапка, меню, курсор | все HTML (`<header>` продублирована), `styles.css` блоки `header` и `custom cursor`, начало `script.js` |
| Скролл-анимации | `animations.js` |

`styles.css` разделён баннерами `/* ===== ИМЯ ===== */`, `script.js` — блоками
`/* ---------- имя ---------- */`. Ищи по имени блока, а не читай файл целиком.

Ассеты: `assets/img/` (фото), `assets/video/`, `assets/fonts/`. Что за какое
фото отвечает, описано в `assets/img/README.md`. Сами бинарники читать не надо.
`assets/_src/` — исходники, на сайте не используются. `docs/` — архив и
референсы, к сайту отношения не имеют. Там же `docs/snippets/` — блоки,
снятые с сайта, но сохранённые целиком, чтобы взять на другой проект.

## Локализация

`i18n.js` держит два словаря, `ru` и `en`, с плоскими ключами вида
`home.hero.title`, `about.03.text`, `service.personal.price`. Префикс ключа
совпадает со страницей. В HTML элементы помечены `data-i18n`, и внутри лежит
**английский вариант как значение по умолчанию**, поэтому при правке текста
надо менять оба места: `i18n.js` и HTML.

## Критические файлы

`i18n.js`, `styles.css`, четыре HTML — сайт целиком. Правки только точечные,
массовый рефакторинг не делаем.

Без отдельного указания не менять: `wrangler.toml`, `.assetsignore`,
`.gitignore`, содержимое `assets/`, `docs/`, имена файлов страниц и URL.

## Правила для текстов

Требования владельца сайта, действуют для обоих языков, включая `<title>`
и `meta description`. Классов CSS, атрибутов и имён файлов не касаются.

1. **Предложения заканчиваются точкой.** В абзацах, лидах, подписях и
   сообщениях формы. Не ставим в заголовках, пунктах меню, на кнопках,
   в тегах-лейблах, ценниках и в пунктах списков, которые не предложения.
2. **Никаких тире и дефисов** в видимом тексте: ни `—`, ни `–`, ни `-`.
   Вместо тире переписываем фразу: запятая, двоеточие или два предложения.
   Составные слова подбираем без дефиса («партнёрские отели», «кредиты на
   spa», «ранний заезд»). Разделитель в названиях страниц и марки — `·`.
   Единственное исключение, о котором попросила владелица: «Консьерж-сервис»
   пишется через дефис, и на главной, и на Service. Не «чинить».
3. **Предлоги и союзы не висят в конце строки.** Короткие служебные и
   однобуквенные слова связываются со следующим неразрывным пробелом
   `\u00a0`; частицы (же, ли, бы) прилипают к слову перед ними. Так же
   разделяются разряды в числах и цена с валютой: `от\u00a020\u00a0000\u00a0₽`.
   В английском связываются только `a` и `I`. Неразрывные пробелы живут
   в `i18n.js`; в HTML остаются обычные, этот текст виден лишь до загрузки
   скрипта.

## Проверка после правок

1. В обеих языковых версиях ни в одном элементе с `data-i18n` нет `—`, `–`
   или дефиса между словами, кроме «Консьерж-сервис». Искать регуляркой
   с флагом `u` (`[\p{L}\p{N}]-[\p{L}\p{N}]`): `\w` в JavaScript
   кириллицу не видит и такой дефис пропустит.
2. Ключи, добавленные в `ru`, есть и в `en`.
3. Поднять `?v=` у изменённых `styles.css` / `script.js` / `i18n.js` /
   `animations.js` во **всех четырёх** HTML, иначе браузеры отдадут кэш.
4. Открыть затронутые страницы в браузере.

## Деплой

Рабочий адрес сайта: https://addressguides.com
(`www.addressguides.com` перенаправляется туда же).

Сайт собирается сам: Cloudflare Workers Builds, проект `adress`, привязан
к `veshkurtsevaa/ADDRESS`, ветка `main`. Через минуту после мержа в `main`
правка на сайте, ничего загружать не нужно. Настройки Worker в
`wrangler.toml`, лишнее из выкладки отсекает `.assetsignore`. Сборки видно
в `adress` → Deployments → Recent builds. Технический адрес того же Worker:
https://adress.wh0isd.workers.dev/

Домен `addressguides.com` зарегистрирован на reg.ru (там его продлевают),
а DNS обслуживает Cloudflare: на reg.ru прописаны NS серверы Cloudflare,
зона `addressguides.com` в том же аккаунте. `addressguides.com` и
`www.addressguides.com` подключены в `adress` → Domains → Custom domains.
Остальные записи зоны (`mail`, `ftp`, `pop`, `smtp`, `MX` на
`hosting.reg.ru`, SPF в `TXT`) перенесены с reg.ru как были; прокси на них
не включать, это ломает почту.
Redirect Rule «Redirect from WWW to root» (301, `https://www.*` →
`https://${1}`) переводит www на `addressguides.com`, а SSL/TLS → Edge
Certificates → **Always Use HTTPS** включён. Сертификат Universal от
Let's Encrypt, Cloudflare продлевает его сам. Эти настройки живут в зоне,
а не в проекте, переезд домена между проектами их не трогает.

Запасной вариант на случай, если GitHub снова станет недоступен:
Cloudflare Pages, проект `address-site`, https://address-site.pages.dev ,
с ручной загрузкой файлов. Собрать папку (четыре HTML, `styles.css`,
`script.js`, `i18n.js`, `animations.js`, `favicon.ico`, папка `assets`
без `_src`), отдать владелице архивом, она загружает его в проект:
**Create deployment** → перетащить папку или zip → **Deploy site**.
Затем убрать домены из `adress` → Domains и добавить их в
`address-site` → Custom domains.

История: с 16 по 26 сентября 2026 аккаунт GitHub был помечен антиспамом,
репозиторий не был виден сторонним приложениям, и сборки `adress` падали
с ошибкой «The project is linked to a repository that no longer exists».
В это время сайт жил в `address-site`. 26 сентября репозиторий заново
подключили в `adress` → Settings → Build, сборки пошли, и домен перенесли
в `adress`. GitHub Pages (https://veshkurtsevaa.github.io/ADDRESS/) после
этого не проверяли, рабочим адресом он больше не считается.

Владелец сайта разрешила мержить самостоятельно: коммит, пуш, пул-реквест
в `main` и сразу мерж, без вопроса «мержить?». Обсуждать нужно сами правки,
а не мерж.
